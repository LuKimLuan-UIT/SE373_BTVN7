Challenge B · Truncation

Kỹ thuật hiện tại: Truncation. Bỏ các lượt hội thoại cũ, giữ N lượt user→assistant gần nhất. Một lượt có thể gồm nhiều tool calls/results; không cắt giữa cặp tool. System instructions đầu phiên được giữ; các ràng buộc trong user message cũ có thể mất.

0 API khi truncation, cả Offline lẫn Provider. Không sinh summary hoặc checkpoint; không tăng usage. History/archive gốc giữ để xem lại, nhưng không tự gửi lại model. Phiên quá ngắn hoặc tool call chưa hoàn tất sẽ từ chối và giữ nguyên context.

Năm kỹ thuật còn lại là hướng mở rộng, chưa bật trong luồng compact B hiện tại. Các báo cáo checkpoint cũ mô tả phiên bản trước.

Context hiện tại: snapshot instructions, memory index, tools và active messages, gồm câu trả lời mới nhất. Ước lượng UTF-8 bytes/4; không gồm archive hay tin nhắn đang gõ. Phiên trống/reset hiển thị 0 · chưa nạp. Usage: tổng input/output provider báo qua các request đã gửi, không phải kích thước context.

Cảnh báo từ 80%, chỉ nhắc người dùng; không tự compact. Đây không phải context window thật của model.

B2 dùng runtime đọc/lọc/đếm log, trả findings có bằng chứng. Offline không gọi LLM; Provider dùng model trong .env. Không chạy Python tùy ý.
